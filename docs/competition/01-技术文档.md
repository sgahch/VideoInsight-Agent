# 项目技术文档
## VideoInsight Agent — 面向多平台视频的智能转写与结构化分析系统

> 参赛组别：高教主赛道 · 本科创意组 · "人工智能+"类（备选：人工智能 OPC 专项）
> 版本：v3.0 | 编制日期：2026年8月

---

## 摘要

VideoInsight Agent 是一套**面向中文互联网多平台视频的智能理解系统**，解决"长视频信息获取效率低、跨平台内容难以统一处理"的痛点。用户提交视频链接或上传本地音视频文件后，系统自动完成 **媒体下载 → 音频提取 → ASR 语音转写 → LLM 结构化分析 → AI 对话问答** 的全流程，输出视频总结、逐字稿、面试复盘（面经提取）等结构化成果，并支持基于转写稿的多轮 AI 对话。

系统已实现：抖音 / B站 / 小红书 / 快手四平台解析、本地文件上传分析、Mock/真实双链路可切换、任务持久化与多客户端数据隔离、用户自备 LLM 模型配置、沉浸式 Web 界面（深色/浅色主题）等完整功能，是可独立运行、可直接演示的成品级系统。

## 一、项目背景与问题定义

### 1.1 痛点分析

| 用户群体 | 痛点 |
|---|---|
| 学习者 | 动辄 30—120 分钟的网课、技术分享视频，无法快速定位核心内容 |
| 求职者 | 面试经验分享视频分散在多个平台，手工整理面经成本极高 |
| 内容从业者 | 需要批量理解竞品视频、行业报告视频 |
| 信息过载用户 | 视频无法像文字一样搜索、摘要、引用 |

**核心矛盾**：视频是信息密度高但**不可检索、不可摘要、不可对话**的媒介形态。现有工具要么只支持单一平台（如 B站自带总结），要么需要用户付费订阅 API，缺乏"多平台 + 结构化分析 + 自由对话"的一体化方案。

### 1.2 目标

构建一个**可部署、可扩展、多用户可用**的视频理解系统，实现：

1. 多平台视频链接的自动化解析与媒体获取；
2. 高精度语音转写（ASR）；
3. 基于大语言模型的三种结构化分析模式（总结 / 逐字稿 / 面试复盘）；
4. 基于任务转写稿的 AI 多轮对话；
5. 历史任务持久化、多客户端数据隔离、用户自备模型等工程化能力。

## 二、系统总体架构

### 2.1 架构总览

```text
┌─────────────────────────────────────────────────────────────────┐
│                       客户端 (Web 浏览器)                        │
│  沉浸式前端：上传/链接分析 · 任务状态 · AI 对话 · 历史记录        │
│  Cookies授权 · 模型设置 · 深色/浅色主题                          │
└──────────────────────────────┬──────────────────────────────────┘
                               │ HTTP / JSON (RESTful API)
┌──────────────────────────────▼──────────────────────────────────┐
│                   FastAPI 应用层 (app/main.py)                  │
│  路由：/analyze /analyze-file /tasks/{id} /tasks/{id}/chat      │
│        /tasks/{id}/media|video /cookies/* /health               │
│  中间件：X-Client-Id 客户端身份识别（任务归属隔离）              │
├──────────────────────────────┬──────────────────────────────────┤
│       工作流编排层 (workflow.py)   │     存储层 (task_store.py) │
│  下载→转写→分析→标题生成的流水线    │   SQLite 任务持久化          │
│  后台任务：BackgroundTasks 异步执行 │   results/*.json 结果落盘   │
├──────────────┬───────────────┬────┴─────────────┬────────────────┤
│ 适配器层 (app/adapters/)                        │  外部依赖       │
│  Downloader │ Audio │ ASR │ LLM                 │  yt-dlp        │
│  Mock/yt-dlp│ ffmpeg│Para-│ OpenAI 兼容         │  ffmpeg        │
│  /快手内置   │ 预处理│former│ (DeepSeek/OpenAI)  │  DashScope ASR │
└──────────────┴───────┴──────┴────────────────────┴────────────────┘
```

### 2.2 分层设计原则

| 层 | 职责 | 设计要点 |
|---|---|---|
| 前端层 | 交互与展示 | 纯静态资源（HTML/CSS/JS），由后端统一托管，无独立部署成本 |
| API 层 | 接口契约 | FastAPI + Pydantic 模型，OpenAPI 文档自动生成 |
| 编排层 | 流程控制 | 固定流水线：下载→转写→分析→标题生成，可替换各环节实现 |
| 适配器层 | 外部能力抽象 | 下载器 / 转写器 / 分析器均定义统一接口，**Mock 与真实实现可热切换** |
| 存储层 | 持久化 | SQLite 存任务元数据，JSON 文件存分析结果，媒体文件独立目录 |

### 2.3 关键架构决策

1. **适配器模式实现"双链路"**：下载、ASR、LLM 三个环节全部抽象为接口，提供 Mock 与真实两种实现。`VIDEOINSIGHT_MOCK_MODE` 环境变量或请求级 `use_mock` 参数决定走哪条链路，**使系统在无外部 API Key、无 ffmpeg 的环境下仍可完整演示**，同时保持真实链路就绪。
2. **SQLite + 文件混合存储**：任务记录（状态机、请求参数）入库，分析结果（大文本 JSON）落盘，兼顾查询效率与数据体积。
3. **客户端身份隔离**：前端浏览器生成持久化 `client_id`，所有请求携带 `X-Client-Id` 头，任务列表/详情/删除/对话/媒体访问均校验归属，**实现多用户数据隔离，无需复杂账号体系**。
4. **用户自备模型**：AI 对话接口支持请求级携带用户的 provider/base_url/model/api_key，**让多租户场景下 LLM 成本由用户自担，平台无需持有任何用户密钥**。

## 三、核心功能模块

### 3.1 多平台媒体获取（Downloader）

**支持平台与策略**：

| 平台 | 策略 | 说明 |
|---|---|---|
| 抖音 / B站 / 小红书 | yt-dlp 匿名下载 | 无需 cookies 即可解析多数公开视频 |
| 快手 | **内置 KuaishouDownloader** | yt-dlp 无快手 extractor，自研解析移动端分享页 `v.m.chenzhongtech.com/fw/photo/<photoId>` 中的 `mainMvUrls` 字段，获取 mp4 直链 |
| 任意链接 / 本地文件 | 上传链路 | `upload://` 协议标识，走文件分析 |

**设计要点**：
- `select_downloader()` 按平台路由到不同实现，支持 cookies 文件（`YTDLP_COOKIES_FILE`）与浏览器 cookies（`YTDLP_COOKIES_FROM_BROWSER`）；
- 下载产物统一为音频（转写用）+ 源视频（按需缓存）；
- Mock 下载器生成本地合成音频，保证无网络环境可演示。

### 3.2 音频预处理（Audio）

- 基于 **ffmpeg**（优先系统安装，缺失时回退 `imageio-ffmpeg` 内置二进制）将任意音视频统一转为 **16kHz 单声道 WAV**，满足 ASR 输入要求；
- 统一预处理管线保证下游转写器输入格式一致。

### 3.3 ASR 语音转写（Transcriber）

| 实现 | 说明 |
|---|---|
| ParaformerTranscriber | 阿里云 DashScope Paraformer 非流式 ASR（`paraformer-realtime-v2`），支持长时间音频、返回带时间戳的分段结果 |
| MockTranscriber | 返回内置示例分段，用于离线演示 |

- 输出统一为 `TranscriptSegment(start, end, text)` 结构；
- 提供 `format_transcript(include_timestamps=True/False)` 两种渲染：带时间戳（对话/详情用）与纯文本（LLM 提示词用）。

### 3.4 LLM 结构化分析（Analyzer）

**三种分析模式**（`AnalysisMode`）：

| 模式 | 输出 |
|---|---|
| `summary` | AI 智能总结：一句话核心 + 内容大纲 + 关键要点 + 行动建议 |
| `transcript` | 逐字稿提取（跳过 LLM 调用，直接返回原文，省时省钱） |
| `interview` | 面试复盘：岗位 / 问题列表 / 回答要点 / 追问反馈 / 复盘建议 |

**提示词工程（V2）**：
- 元信息注入：标题 / 作者 / 平台 / 时长；
- **硬性兜底规则**：歌词/噪音/空文本直接输出拒绝提示，禁止强行总结；
- 输出格式契约：固定 Markdown 板块、不可删减、字数约束；
- 忠实度约束：仅依据转写文本，禁止脑补画面，不确定信息标注 `[存疑]`。

### 3.5 AI 对话（Chat）

- 接口：`POST /tasks/{task_id}/chat`，仅允许对**已完成且有转写稿**的任务提问；
- 对话上下文 = 该任务的转写稿 + 元信息，**不引入外部知识**（防止幻觉）；
- **用户自备模型**：请求可携带 `llm_provider / llm_base_url / llm_model / llm_api_key`，后端优先使用用户配置，未提供时回退服务端配置；
- 前端未配置 Key 时引导用户先到"模型设置"配置，保证对话真实可用。

### 3.6 任务标题自动生成（AI 摘要命名）

- 分析完成后从输出中提取"一句话核心 / 核心观点 / 面试岗位"生成 ≤30 字任务标题；
- 历史任务列表以 AI 摘要命名展示（替代固定模式名），**每个历史任务名称唯一且语义化**。

### 3.7 Web 前端

- 沉浸式暗黑/浅色双主题（CSS 变量驱动，偏好持久化）；
- 功能区：本地文件分析、在线链接抓取、任务实时进度（0→100% 流动动画）、结果三视图（总结/逐字稿/JSON）、AI Agent 对话、历史任务、Cookies 授权、模型设置；
- 纯原生 JS 实现（无前端框架依赖），`fetch` + 极简 Markdown 渲染，零构建步骤。

## 四、数据模型与持久化

### 4.1 核心数据模型（app/schemas.py）

```text
AnalyzeRequest   url / mode / use_mock / client_id
TaskRecord       task_id / status / request / created_at / updated_at
                 result / error
AnalysisResult   mode / transcript / segments[] / output / media
                 title / artifacts / diagnostics
MediaInfo        audio_path / title / author / duration / source_url
ChatRequest      question / llm_provider / llm_base_url / llm_model / llm_api_key
```

### 4.2 任务状态机

```text
queued ──► running ──► succeeded
   │          │
   └──────────┴──────► failed
```

- 后台任务（`BackgroundTasks`）异步执行，前端 2s 轮询 `GET /tasks/{id}` 获取状态；
- 失败任务记录错误信息，支持历史查看与一键删除（级联清理结果 JSON 与临时媒体文件）。

### 4.3 持久化布局

```text
data/videoinsight.db     SQLite：任务元数据（含 client_id 归属列，自动迁移）
data/results/<task_id>.json   分析结果
data/tmp/<task_id>/            临时转写文件
media/<task_id>/               已存媒体文件
media/_cookies/cookies.txt    平台 cookies
```

## 五、安全与多用户设计

| 能力 | 实现 |
|---|---|
| 多客户端任务隔离 | `X-Client-Id` 请求头 + SQLite `client_id` 列；列表仅返回本客户端任务；他人任务详情/删除/对话/媒体一律 404（不暴露存在性） |
| 用户密钥零托管 | LLM Key 仅存浏览器 localStorage，仅随单次请求传递，服务端不持久化、不入库 |
| Cookies 文件 | 存于服务端 `media/_cookies/`，支持上传/粘贴/浏览器扫码抓取三种方式归一化写入 |
| 上传安全 | 上传文件按任务目录隔离存储，删除任务时级联清理 |
| 前端安全 | 所有后端内容渲染前 HTML 转义 + 白名单 Markdown 渲染，防 XSS |

## 七、创新点总结

1. **多平台统一理解**：抖音/B站/小红书/快手四平台 + 本地文件统一接入同一分析流水线，其中快手采用**自研分享页解析器**填补 yt-dlp 能力空白；
2. **Mock/真实双链路架构**：通过适配器模式实现"无 Key 可演示、有 Key 即真实"，降低系统落地门槛，也便于教学与评审演示；
3. **用户自备模型的多租户方案**：LLM 密钥零托管，对话成本由用户自担，天然适配多用户部署与商业化；
4. **无账号体系的数据隔离**：以浏览器持久化 client_id 实现轻量多用户隔离，兼顾隐私与易用性；
5. **AI 摘要任务命名**：自动为每个分析任务生成语义化标题，改善历史任务检索体验；
6. **工程完整性**：自动数据库迁移、级联清理、沉浸式双主题 UI、提示词硬兜底（防幻觉/防噪音），达到可交付水准。

## 八、部署与运行

### 8.1 环境要求

- Python 3.10+；ffmpeg（可选，缺失时自动回退内置二进制）；
- 真实链路需：DashScope API Key（ASR）、OpenAI 兼容 LLM Key（总结/对话）。

### 8.2 启动方式

```bash
pip install -r requirements.txt            # 基础依赖
pip install -r requirements-asr.txt        # 真实 ASR 链路
cp .env.example .env                       # 配置密钥
uvicorn app.main:app --host 0.0.0.0 --port 8000   # 单进程启动（任务为进程内后台任务）
```

### 8.3 演示路径（无任何外部依赖）

```text
Mock 模式（VIDEOINSIGHT_MOCK_MODE=true 或请求 use_mock=true）：
提交链接/上传文件 → 任务 0→100% 进度 → 查看总结/逐字稿/JSON → 模型设置填 Key → AI 对话
```
