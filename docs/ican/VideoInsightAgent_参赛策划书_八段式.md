## 01 行业痛点（Industry Pain Points）
> 条数与下方「03 核心功能」严格 1:1 对应（4 痛点 ↔ 4 功能）。

1. **获取难**：抖音/快手/B站/小红书链接格式混杂，第三方下载站不稳；抖音下载接口已强制 `a_bogus` 签名校验（通用工具至 2026.08 仍普遍 403），无登录态几乎拿不到无水印源。
2. **整理慢**：拿到视频后需手动上传转写、手动喂大模型、手动整理，结果无统一结构，单条长视频吸收耗时以小时计，无法批量。
3. **不闭环**：文字到手后无法就内容继续追问，观众评论等反馈信号未被利用，吸收停留在"看完"而非"掌握"。
4. **难复用**：通用工具只跑一次、无持久化、无并发与故障恢复，无法作为稳定可复用的服务，团队/个人知识无法沉淀。

- **页脚总括**：传统"下载—转写—整理"人工链路，难以适配短视频时代的知识吸收需求。

## 02 技术架构（Technical Architecture）
> 项目类型：AI 软件 / 大模型应用，四层采用「数据 — 模型 — 服务 — 应用」。

- **数据层（Data）**：链接解析归一化（分享文案→干净链接）+ 多平台下载（抖音免签名直连 / yt-dlp 兜底 / 本地上传）+ ffmpeg 音频预处理（16kHz 单声道 WAV）。
- **模型层（Model）**：DashScope Paraformer 语音转写（长音频切片并发）+ OpenAI-compatible LLM（DeepSeek 等）结构化分析与多轮问答，Prompt 模板驱动。
- **服务层（Service）**：FastAPI 异步服务 + SQLite 持久化（按客户端身份隔离）+ 有界线程池 + 重启对账 + 产物自动回收 + 可选共享令牌鉴权中间件（默认拒绝 + 白名单）。
- **应用层（Application）**：原生 Web 前端四视图（总结 / 逐字稿 / 评论 / JSON）、在线播放、AI 追问、深浅主题。

- **页脚总括**："数据—模型—服务—应用"四层架构，把分散的下载、转写、分析、问答收敛成一个可复用的软件系统。

## 03 核心功能（Core Functions）— 共 4 个模块，与痛点 1:1

### 3.1 多平台链接即获取（对应痛点 1）
- **链接归一化**：从"复制打开抖音看看【…】《…》https://…"类分享文案中自动裁剪出干净链接与标题标签【实测】。
- **免签名下载**：抖音改走移动分享页 SSR 内嵌直链，无需登录态、无需 `a_bogus` 签名，解决通用工具 403 失效【实测】。
- **多源兜底**：快手/B站/小红书走 yt-dlp；本地文件上传单文件上限 **2048 MB**【系统默认配置】，彻底绕开平台风控。
- **页脚总括**：4 平台链接即分析，抖音免签名直连 + 本地上传双兜底，获取成功率不再被平台签名墙卡死。

### 3.2 语音转写与结构化总结（对应痛点 2）
- **切片并发转写**：长音频（默认 >900s）自动切分为约 600s 片段、最多 3 路并行转写【系统默认配置】。
- **自学习进度校准**：进度条数据源取自历史诊断记录，动态学出转写吞吐中位数约 **8× 实时**、非转写开销中位数约 **81s**，并自动过滤 Mock 脏数据【基于历史诊断数据自学习估算】。
- **三模式分析**：`transcript` 逐字稿 / `summary` 结构化总结 / `interview` 面经与知识点提取【实测】。
- **页脚总括**：长音频切片并发 + 真实进度自学习，把"等结果"变成可信的分钟级交付。

### 3.3 评论接入与可追问助手（对应痛点 3）
- **零依赖评论抓取**：抖音评论走内置直连接口，不需爬虫、不需浏览器、不需登录态【实测】。
- **降级不阻断**：评论抓取失败仅静默降级，绝不阻断下载/转写/总结主链路【实测，178 测试覆盖】。
- **可追问 AI**：任务完成后基于该视频转写稿多轮问答，支持用户自备模型配置，模型只依据本视频内容作答【实测】。
- **页脚总括**：评论与主链路解耦 + 基于转写稿的可追问助手，吸收从"看完"升级为"问懂"。

### 3.4 稳定可复用的服务体系（对应痛点 4）
- **质量基线**：**178 项**自动化测试全部通过，覆盖下载路由、评论解析、ASR 切片容错、任务隔离、并发闸门、重启对账、鉴权边界、产物回收安全边界【实测】。
- **稳定服务**：默认 2 路有界并发线程池；进程重启自动对账（running→失败、queued→重入队）【实测】。
- **安全与回收**：产物定时回收（孤儿目录 / 中间 WAV / 过期记录），下划线目录永不误删；可选共享令牌鉴权采用"默认拒绝 + 公开白名单"中间件【实测】。
- **页脚总括**：178 测试 + 有界并发 + 自恢复 + 鉴权，把"能跑一次"做成"能稳定服务"。

## 05 使用方法（How to Use）

- **平台接入**：浏览器直接访问 Web 端；或调用 `POST /analyze` 接口（支持 API 集成）。
- **主流程**：粘贴链接（或上传文件）→ 选模式（transcript / summary / interview）→ 提交，系统自动完成下载→转写→分析。
- **状态监控**：实时查看任务进度、阶段与 ETA；媒体在线预览与下载，支持 Range。
- **复盘**：历史任务按客户端身份隔离持久化，可随时回看、删除或继续 AI 追问。

- **页脚总括**：粘贴即分析、进度可观测、历史可回溯——三步上手，零配置可跑（内置 Mock 开箱即用）。

## 06 应用场景（Scenarios）

### 场景 1：求职 / 学习复盘
- **场景描述**：面试视频、技术分享、课程与播客，传统"下载—转写—整理"单条耗时数小时【基线】→ 粘贴链接数分钟得结构化总结与面经【改进后】。
- **平台应用**：`interview` 模式提取面试问题、回答要点与复盘建议；`summary` 模式生成课程要点时间线。
- **核心成效**：单条长视频吸收耗时从小时级压缩至分钟级（效率提升以数量级计）。

### 场景 2：内容创作与竞品分析
- **场景描述**：创作者基于抖音/B站热门视频做二次创作，传统需反复观看记录【基线】→ 系统输出逐字稿 + 评论热词 + 结构化摘要【改进后】。
- **平台应用**：四视图一键切换，评论热词辅助选题；导出 JSON 进入自有工作流。
- **核心成效**：脚本整理与选题调研周期显著缩短。

### 场景 3：企业 / 团队内训归档
- **场景描述**：培训视频散落难检索【基线】→ 统一转写沉淀、可追问检索【改进后】。
- **平台应用**：本地私有部署，原始音视频短期留存、可一键删除，满足隐私要求。
- **核心成效**：内部知识从"看完即忘"变为"可检索复用"。

- **页脚总括**：学习、创作、企业三类场景均已闭环可用，价值以"时间压缩"量化。

## 07 改进建议（Improvement Suggestions）
> 反套路坦诚：主动暴露短板，与第 03/04 段卖点形成张力；交付口径统一为"当前差距 / 目标值，非已达成"。

- **技术优化**：ASR 中文转写准确率依赖云端模型，离线/弱网场景受限；评论抓取目前仅抖音内置直连（约 10 条一级热门评论），多平台评论需外接 MediaCrawler（规划值）。
- **运营挑战**：当前为单机进程内线程池 + SQLite，横向扩展需引入 Celery + Redis、PostgreSQL（规划值）；规模化部署成本待评估。
- **安全风险**：鉴权为单共享密钥，尚无账号体系与权限粒度；原始音视频生命周期管理需进一步强化。
- **标准与合规**：各平台下载接口频繁变动（如抖音 `a_bogus`），需持续维护适配，互通稳定性受平台策略影响。

- **页脚总括**：以专业所学正视短板，持续迭代——不断深化改进、报社会之需。
