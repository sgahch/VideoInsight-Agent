## 一、项目一句话

**粘贴一条视频链接，自动完成下载、语音转写、结构化总结、观众评论提取，并提供一个可以追问的 AI 助手——把"看视频学东西"从数小时的重复劳动压缩到几分钟。**

---

## 二、需求与痛点（对应评分：作品实用性 25 分）

抖音、B站、小红书、快手上的学习类、经验类、技术分享类视频极大丰富，但**吸收效率极低**：

1. 复制链接 → 第三方网站下载音频 → 上传转写工具 → 手动喂给大模型 → 再手动做事实核查，步骤多、耗时长。
2. 依赖人工操作，无法批量处理，结果没有统一结构，难以沉淀和复用。
3. 第三方下载站稳定性、合规性不可控；通用转写工具不适合做自动化后端。

**我们的解法**：做成一个**可运行的软件系统**，用户粘贴链接即返回逐字稿、结构化总结、观众评论与一个可追问的 AI 助手，全流程自动化、可复用、可审计。

---

## 三、产品与技术架构（对应评分：技术方案 20 分）

**整体工作流**：链接 / 分享文案 → 解析归一化 → 下载 → ffmpeg 音频预处理 → ASR 切片并发转写 → LLM 结构化分析 → 结果落盘 → Web 四视图呈现。

**技术栈**：

| 环节 | 方案 |
|---|---|
| 后端 | FastAPI（异步友好，适合 API 服务） |
| 持久化 | SQLite（任务、结果、历史，按客户端身份隔离） |
| 音频处理 | ffmpeg（提取 16kHz 单声道 WAV、切片） |
| 语音转写 | DashScope Paraformer（长音频自动切片、多路并发） |
| 大模型分析 | OpenAI-compatible LLM（DeepSeek 等），Prompt 模板驱动 |
| 前端 | 原生 Web 页面（结果四视图、在线播放、深浅主题） |

**三种分析模式**：`transcript`（带时间戳逐字稿）、`summary`（结构化总结）、`interview`（面经 / 知识点提取）。

**已落地能力**：链接即分析（抖音/快手/B站/小红书短链与分享文案自动归一化）、逐字稿、AI 总结、观众评论抓取、AI 追问、本地上传兜底、历史隔离、可选访问鉴权。

---

## 四、核心创新点（对应评分：创新性 35 分 — 答辩重点）

我们没有停在"接一个大模型 API"，而是在**工程链路**上做了四个有辨识度的创新：

**1. 真实进度自学习校准**
进度条的数据源是历史诊断记录里的真实运行数据（媒体时长 / 转写耗时 / 总耗时）。系统动态学习转写速度中位数（约 8× 实时）与非转写开销中位数（约 81 秒），据此推算进度、阶段与剩余时间，并**自动过滤 Mock 脏数据**——让进度条从"装饰性动画"变成可信的工程信号。

**2. 抖音下载绕过 a_bogus 签名墙**
yt-dlp 的抖音提取器依赖的接口已强制 `a_bogus` 签名校验（至 2026.08 仍未实现，带 Cookie 也一律 403）。我们改走移动分享页 SSR：其内嵌数据里直接给出视频地址，再拼无水印直链下载，**无需登录态、无需签名**，解决了同类工具普遍失效的痛点。

**3. 评论链与主链路解耦 + 零依赖抓取**
观众评论抓取被刻意排在下载之前（只一次轻量请求），且**失败只静默降级，绝不阻断**主分析链路。抖音评论走内置直连接口，不需要部署爬虫、不需要浏览器、不需要登录态。

**4. 全链路自恢复与可观测**
长任务改用专用有界线程池（不再挤占请求线程）；进程重启时做对账——`running` 标记失败、`queued` 重新入队；产物自动回收（孤儿目录、中间 WAV、过期记录），下划线目录永不误删；可选共享令牌鉴权采用"默认拒绝 + 公开白名单"中间件。把"能跑一次"做成"能稳定服务"。

## 六、应用场景与价值（对应评分：实用性 25 分 — 商业模式 / 社会与 market 价值）

| 用户 | 典型场景 |
|---|---|
| 求职者 / 学生 | 面试视频复盘、面经提取、课程与播客快速摘要 |
| 内容创作者 | 文案 / 标题提取、脚本整理、竞品分析 |
| 企业 / 团队 | 培训视频归档、内部资料检索、会议纪要 |

**落地模式**：以本地私有部署为主（隐私优先，原始音视频短期留存、可一键删除），可叠加轻量 SaaS 按调用量计费，成本可控。**社会价值**在于降低优质视频知识的吸收门槛，让"看视频学习"可沉淀、可检索、可复用。
